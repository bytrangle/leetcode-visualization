Technical Specification

Leet Years

status: approved

A self-hosted tool that replays your own LeetCode practice history as a difficulty-colored heatmap. Canonical source: devpost/spec.md.

The architecture in one line: a Node CLI + local server (Node/TypeScript + Express) fetches your full submissions through leetcode-query using your own session cookie, transforms them, and serves a React player that runs the replay. The cookie stays server-side and in-process — never in the browser, never with a third party.

How data flows

Components, by PRD behavior

Setup & authentication

bin/cli.ts reads args (--demo), prompts for the cookie (or reads LEETCODE_SESSION), then orchestrates the run. server/leetcode.ts holds the cookie and fetches submissions.

PRD ref: prd.md > Setup & authentication

  • Prompt: masked input, cookie held in-process only.
  • Failure → terminal message + exit, no browser.

Data & server

server/transform.ts builds the years → days → problems shape. server/http.ts serves /api/submissions + the built frontend, then opens the browser. server/sampleData.ts backs --demo.

Player

src/App.tsx fetches /api/submissions once, then holds the replay state (idle/playing/paused/ended + current year/day, seek). src/lib/replay.ts owns the timeline/seek logic.

PRD ref: prd.md > Replay, prd.md > Controls

Heatmap & year transitions

src/components/Heatmap.tsx renders the 7×~53 grid and drives the whole-grid card flip. src/components/Cell.tsx is one day (grey→color flip + hover). src/lib/colors.ts maps difficulty → score (1/2/4) → gradient color.

PRD ref: prd.md > Year transition, prd.md > Look and Feel

Popup & controls

src/components/Popup.tsx lists a day's problems with difficulty dots. src/components/Controls.tsx is the play/pause toggle (always shown) + seek bar (shown only when history > ~20s).

PRD ref: prd.md > Popup, prd.md > Controls

Decisions & risks

Learner choices: React; TypeScript; self-hosted npx CLI + local server; session-cookie auth through leetcode-query.

Derived details: Express, Vite, file layout, --demo sample mode, transform shape.

Worked through: "Is pasting my session cookie good practice?" → yes, only for a self-hosted personal tool; the local server keeps it out of the browser.

Verify first in build: leetcode-query still returns full submissions (title + difficulty + timestamp) from current LeetCode GraphQL.

Run it

  • npm install then npm run dev (develop).
  • npm run build && npm start → paste cookie → browser opens.
  • npm start -- --demo → labeled sample data, no cookie.
  • No deployment — a cookie-authenticated tool is local by design. Demo = screen-record your own replay.

Failure modes (the ones that matter)

  • Bad/expired cookie → "Couldn't authenticate — check your session cookie." + exit.
  • LeetCode down/rate-limited → "Couldn't reach LeetCode — try again." + exit.
  • No solved problems → "This account hasn't solved any problems yet." + exit.
  • leetcode-query broken → --demo (labeled), never fake live data.
